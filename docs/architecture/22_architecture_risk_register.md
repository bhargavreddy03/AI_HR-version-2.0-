# Architecture Risk Register

This document identifies, evaluates, and establishes mitigation controls for strategic architectural, security, operational, and regulatory risks in the target SaaS platform.

---

## 1. Architectural Risk Evaluation Matrix

| Risk ID | Category | Risk Description | Likelihood | Impact | Severity | Mitigation Strategy & Architectural Controls |
|:---:|:---|:---|:---:|:---:|:---:|:---|
| **AR-01** | **Multi-Tenancy** | **RLS Configuration Bypass**: A misconfigured database migration or unauthenticated raw SQL query could bypass PostgreSQL Row-Level Security, causing cross-tenant data exposure. | Low | Critical | **High** | Mandate `FORCE ROW LEVEL SECURITY` on all tenant tables; execute automated RLS assertion tests in CI; run application connection pool with non-superuser credentials. |
| **AR-02** | **Performance** | **Large PDF / OCR Processing Exhaustion**: A sudden influx of large or complex scanned resumes could overwhelm worker container CPU and RAM, starving other background jobs. | Medium | High | **High** | Enforce a strict $15\text{ MB}$ upload ceiling; isolate OCR workloads on a dedicated Celery worker queue (`ocr_queue`) with auto-scaling ECS containers and concurrency caps. |
| **AR-03** | **Compliance** | **Algorithmic Bias / Adverse Impact**: Unintentional proxy variables in job descriptions or qualification matching could lead to disparate impact across protected demographic groups. | Medium | Critical | **High** | Completely exclude demographic data (age, gender, ethnicity); implement automated 4/5ths Disparate Impact testing prior to screening model releases. |
| **AR-04** | **Financial** | **LLM Token Cost Overrun**: Unbounded recruiter question generation or resume summarization requests could cause runaway API costs on AWS Bedrock or OpenAI. | High | Medium | **Medium** | Enforce per-tenant monthly token quotas; cache generated interview questions in Redis; use cost-efficient models (e.g. Claude 3.5 Sonnet / Haiku). |
| **AR-05** | **Data Integrity** | **Vector Similarity Drift**: Upgrading or changing the embedding model (e.g. from 1536 dims to 3072 dims) invalidates existing `pgvector` indexes across millions of documents. | Low | High | **Medium** | Store `model_name` and dimension metadata in the `embeddings` table; maintain a background Celery re-indexing task for seamless model version migrations. |
| **AR-06** | **Availability** | **Redis Message Broker Failure**: An outage in ElastiCache Redis could stall task dispatching and drop in-flight notifications or report jobs. | Low | High | **Medium** | Deploy Amazon ElastiCache Redis in Multi-AZ configuration with automatic failover and append-only file (AOF) persistence. |
| **AR-07** | **Security** | **Document Pre-Signed URL Leakage**: A candidate or recruiter forwarding a pre-signed S3 download URL could expose candidate resumes to unauthorized recipients. | Medium | Medium | **Medium** | Restrict presigned URL expiration to $15\text{ minutes}$; enforce IP-address or user-agent validation where supported; audit all download URL generation events. |
| **AR-08** | **Concurrency** | **High-RPS Outbox / Deletion Lock Contention**: Under extreme concurrent load (1,000+ RPS), concurrent user offboarding, organization deletions, and Celery outbox workers could experience lock acquisition timeouts if lock ordering is violated by unvetted custom queries. | Low | High | **Medium** | Mandate strict linear lock hierarchy (Level 0 $\rightarrow$ Level 5) across all transactions; validate with automated PostgreSQL 16 isolation tests (`pg_isolation_test` / Locust) during Step 3 implementation testing. |
| **AR-09** | **Availability** | **Redis Cluster Invalidation Disruption**: A transient Redis split-brain or network partition during high-volume revocation dispatching could cause partial Redis cache update failures. | Low | High | **Medium** | Atomic database `force_authoritative_check = TRUE` gate forces authoritative PostgreSQL fallback on cache miss/stale version; execute implementation-stage chaos engineering tests simulating Redis node restarts. |
| **AR-10** | **Data Integrity** | **Outbox Retention Purge Referential Integrity**: Improper historical outbox pruning could attempt to delete unacknowledged events or disrupt audit tracking. | Low | Medium | **Low** | Enforce `idx_auth_outbox_retention_purge` on `(processed_at, created_at)` filtering `WHERE processed_at IS NOT NULL AND created_at < NOW() - INTERVAL '90 days'`; deletion trigger `fn_prevent_delete_pending_outbox()` blocks deletion of unprocessed rows. |
